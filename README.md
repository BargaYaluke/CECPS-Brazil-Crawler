# 巴西招投标爬虫 · 新手上手指南

---

## 一、这个项目是做什么的?

巴西政府每天在一个叫 **PNCP** 的官方网站(`pncp.gov.br`)上公布全国的采购招标。
信息海量、全是葡萄牙语、还混着大量对中国企业没价值的标(比如只给本地小公司的)。

**这个项目就是你的"巴西采购情报助理"**:每天替你去那个公告栏,
把招标**抄回来 → 扔掉没用的 → 补上背景信息 → 按你的生意方向分类 → 做成一份中文 Excel 报表**。

服务于六大商机方向:**数字经济 / 医疗医药 / 高端制造 / 大宗商贸 / 跨境电商 / 文化体育**。

---

## 二、它是怎么工作的?(6 步流水线)

把它想象成一条**流水线**,招标数据从左流到右,每一站做一件事:

```
采集 ──→ 存储 ──→ 过滤 ──→ 富化 ──→ 分类 ──→ 导出
 抄回来   存进库   扔垃圾   补背景   贴标签   做报表
```

| 站 | 通俗比喻 | 干了什么 |
|---|---|---|
| **采集** | 派助理去公告栏抄 | 从 PNCP 拉招标/合同/计划,原文存到 `data/raw/` |
| **存储** | 录入档案柜 | 存进本地数据库 `data/procurement.db`(SQLite),重复抄不会乱 |
| **过滤** | 扔掉没用的传单 | 按规则丢弃"直采/独家/中小微专属"等对中企无价值的标 |
| **富化** | 给每条标贴便签 | 金额折人民币、标注大区、查机构底细、把品类编号翻译成人话 |
| **分类** | 按生意方向归档 | 用关键词把每条标打到六大维度 |
| **导出** | 打印成报表 | 生成多页中文 Excel,业务直接打开看 |

**两个关键设计**(出问题时能救命):
- **可重复跑不会脏**:同一条招标抄两次只会更新、不会变两条。所以**任何命令中断了,直接重跑就行**。
- **原文留底**:每次抓的原始数据都存在 `data/raw/`,方便回溯。

## 三、快速开始

**第一次用,每个新的 PowerShell 窗口先跑这一行**(否则中文会乱码):

```powershell
$env:PYTHONIOENCODING="utf-8"; chcp 65001 > $null
cd C:\巴西爬虫
```

## 四、运行脚本逐行讲解

> 时间范围 `--start/--end` 按你需要改。下面以"抓 5/22~5/28 这一周"为例。

### ① 抓招标 + 明细

```powershell
python -m src.cli fetch-and-store --start 2026-05-22 --end 2026-05-28 --itens-concurrency 8
```
**比喻**:派助理去公告栏,把这一周所有招标**整页抄下来**,再对每条招标**翻到背面把购物清单也抄上**。
- `fetch-and-store` = 抓招标主表 + 每条的明细(itens),都存进库。
- `--itens-concurrency 8` = 抄"购物清单"时**同时派 8 个助理并行抄**(一条招标要单独发一次请求,几千条很慢,并行加速)。被限速时可降到 3~5。
-  抄完主表后会进入**静默拉明细**阶段(屏幕不动很正常,后台在跑,约 15~25 分钟)。只想要主表、不要明细就加 `--skip-itens`,几十秒搞定。
-  这里**故意没写 `--page-size`**:招标接口每页上限只有 50,写大了会报错(代码会自动帮你压回 50)。

### ② 抓已签合同(看竞争对手)

```powershell
python -m src.cli fetch-contratos --start 2026-05-22 --end 2026-05-28 --page-size 500
```
**比喻**:去查"已经成交的订单",看**谁中标了、签了多少钱** —— 这是竞品情报。
- `--page-size 500` = 每页抓 500 条(合同接口允许,比招标快)。

### ③ 抓年度采购计划 PCA(看未来商机)

```powershell
python -m src.cli fetch-pca --start 2026-05-22 --end 2026-05-28 --page-size 500 --limit 3000
```
**比喻**:政府提前公布的**"明年购物计划"** —— 让你**提前半年到一年**知道谁要买什么,好提早布局。
-  `--limit 3000` = **最多抓 3000 个计划就停**。这是**必须的护栏**:这一周的计划多达约 **192 万条**,不限量会跑几小时、撑爆库。
- 注意:3000 数的是"计划单",每单含多个采购项,实际入库行数会是几万。

### ④ 抓标准品类目录(一次性)

```powershell
python -m src.cli fetch-catalogo --tipo both
```
**比喻**:下载一本**"商品分类大词典"**(政府的 CATMAT 物料 + CATSER 服务编码)。招标里的品类都是冷冰冰的编号,有了这本词典才能翻译成"办公椅""医疗服务"这种人话。
- `--tipo both` = 物料词典(34 万条)+ 服务词典都灌一遍,约几分钟。
- 这是**参考数据,一次性**。以后出报表加 `-SkipCatalog` 跳过。

### ⑤ 抓招标全文 PDF(慢,可选)

```powershell
python -m src.cli fetch-editais --limit 100
```
**比喻**:把招标的**完整文件 PDF 下载下来通读**,从正文里揪出"保留份额""本地生产要求"这类藏在细节里的排除条款,做二次过滤。
-  **很慢,一条约 30 秒**,所以必须 `--limit`。不急可以先跳过。

### ⑥ 富化(补背景信息)

```powershell
python -m src.cli enrich
```
**比喻**:给每条已入库的招标**贴便签**:① 金额按汇率折成人民币;② 根据州标注"东南/南部"大区和经济分层;③ 查采购机构的底细(规模/活跃度);④ 把明细的品类编号用④的词典翻译成人话。
- 想给机构补官方全名加 `--with-brasilapi`(会慢些)。

### ⑦ 分类(贴生意标签)

```powershell
python -m src.cli classify
```
**比喻**:像分拣员一样,读每条招标的标题正文,**贴上六大维度标签**(数字经济/医疗医药/…)。改了关键词词典想重贴,加 `--redo`。

### ⑧ 导出 Excel 报表

```powershell
python -m src.cli export-excel --out data/exports/report.xlsx
```
**比喻**:把档案柜里的数据**打印成一份漂亮的中文 Excel**,业务直接打开分析。
- 产出在 `data/exports/report.xlsx`,共 **7 个 Sheet**:招标主表 / 采购明细 / 已签合同 / 年度采购计划 / 机构画像 / 维度透视 / 过滤审计。

## 五、看懂屏幕输出的指标

跑命令时会刷出一些数字,对照这张表:

### 抓取阶段
| 指标 | 含义 |
|---|---|
| `本页 N 条 / 累计 M` | 这一页抓到 N 条,到目前共 M 条 |
| `服务端 X` | PNCP 告诉你符合条件的**总共有 X 条**(衡量你抓了多大比例) |
| `itens=N` | 抓到的招标**明细**总行数 |

### 过滤阶段:`keep=8357 filtered=0`
| 指标 | 含义 |
|---|---|
| `keep` | **保留**的招标数(有价值,留下) |
| `filtered` | 被**丢弃**的数(命中下面的硬过滤规则) |
| `硬过滤命中 F00x` | 为什么被丢。**F001**=直采/**F002**=独家供应/**F003**=中小微专属/**F004**=保留份额/**F005**=本地生产要求/**F006**=交付期过短 —— 全是对中国企业没机会的标 |
| `软标注命中 T00x` | 保留但打标签。**T001**=长期机会(认证入库制)/**T002**=竞争性招标/**T003**=电子反向拍卖 |

> 例:`软标注命中 T003=6238` = 有 6238 条是"电子反向拍卖"(巴西最常见的招标形式)。

### 富化阶段:`region=59 fx=59 orgaos=49`
| 指标 | 含义 |
|---|---|
| `region` | 补了**大区/经济分层**的招标数 |
| `fx` | 折算了**人民币金额**的招标数 |
| `orgaos` | 生成了**机构画像**的机构数 |

### 分类阶段:`classified=46 uncategorized=13`
| 指标 | 含义 |
|---|---|
| `classified` | 成功打上维度标签的数 |
| `uncategorized` | 没匹配到任何维度的数(占比高说明词典要补,改 `config/dimension_keywords.yaml`) |
| `维度分布` | 各维度各有多少条 |

## 六、常见问题

| 情况 | 怎么办 |
|---|---|
| 中文乱码 / GBK 报错 | 跑命令前先 `$env:PYTHONIOENCODING="utf-8"; chcp 65001` |
| 屏幕卡住不动(抓完主表后) | 正常,在静默拉明细,等几分钟;急可 `Ctrl+C`(主表已保存,明细可重抓) |
| 某步报错 / 中断了 | 直接**重跑那条命令**即可,数据不会重复(幂等设计) |
| 报错 `400 Tamanho de página inválido` | 招标接口每页上限 50,别对 `fetch-publicacao/atualizacao/proposta` 用大 `--page-size`(现已自动夹取) |
| PCA 跑太久 / 太多 | 一定要带 `--limit`,或把日期范围缩到一两天 |

## 七、数据存在哪

```
data/
├── raw/              抓回来的原始数据(留底)
├── procurement.db    本地数据库(所有结构化数据)
├── filtered_log/     被过滤掉的记录(审计用,可追溯为什么被丢)
└── exports/          导出的 Excel 报表 ← 你最终要的东西
```
